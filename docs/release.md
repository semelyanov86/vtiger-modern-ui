# ModernUI 1.0.0

Устанавливаемый модуль для Vtiger CRM Open Source 8.4 со стандартным layout v7.
Рабочие списки, карточки поверх списка, формы, навигация, системные настройки и редактор
ModernUI оформлены по облачному образцу. Бизнес-логика, права и сохранение остаются у CRM.

Приёмка релиза 1.0.0 завершена 2026-11-14. Архивы доступны в разделе
**GitHub Releases** этого репозитория, тег **v1.0.0**.

## Артефакты и проверка скачанного файла

В разделе **Releases** репозитория выбирайте:

- `ModernUI-1.0.0.zip` — устанавливаемый модуль с production assets и notices.
- `ModernUI-source-1.0.0.zip` — исходники, lockfile, инструкции и инструменты разработки.
- `ModernUI-1.0.0.SHA256SUMS` — SHA-256 обоих архивов.
- `ModernUI-1.0.0.files.txt` и `ModernUI-source-1.0.0.files.txt` — SHA-256, размер и путь каждого файла.
- `ModernUI-1.0.0.build.json` — версии инструментов, хэш lockfile и результат двух независимых сборок.

Автоматический GitHub «Source code (zip)» — снимок Git, он не устанавливается в CRM.
В менеджер модулей загружается только `ModernUI-1.0.0.zip`.

```bash
sha256sum --ignore-missing -c ModernUI-1.0.0.SHA256SUMS
```

## Платформа и границы поддержки

| Область | Поддержка и проверенная граница |
|---|---|
| CRM | Vtiger Open Source 8.4, layout v7; проверены официальная 8.4.0 и модифицированный dev-стенд 8.4.0 |
| PHP | Код совместим с 8.1–8.5; установка/браузерные сценарии — 8.1.34 и 8.5.12; 8.4.27 — lint/unit |
| СУБД | MySQL 8.4.13, utf8mb3 и utf8mb4; MySQL 8.0 и MariaDB отдельно не проверены |
| URL | Корень сайта и `/vtigercrm/` |
| Браузеры | Chromium 153.0.8010.12, Firefox 155.0 и WebKit 26.6; минимумы CSS — Chrome/Edge 105, Firefox 121, Safari 15.4, не матрица испытанных старых версий |
| Языки темы | RU/EN/DE с английским fallback, включая собственные настройки, ошибки и доступные подписи |

Vtiger 7.x, 8.0–8.3, 9.x и облачный SaaS не поддерживаются. Тема не переводит чужие поля,
ядро и расширения: для них нужен соответствующий языковой пакет CRM. На чистой CRM только
с `en_us` немецкие и русские тексты ModernUI работают независимо от него.

Известные ограничения ядра и точная матрица расширений — [compatibility.md](compatibility.md).
В официальной 8.4.0 PHP 8.5 может давать native-ошибки дат календаря и deprecated без темы;
ModernUI не исправляет ядро. Почтовый клиент с подключённым внешним ящиком не проверен.
Строгая CSP у темы не требует `unsafe-eval`, но некоторые функции самого v7 его требуют.

## Установка администратором

1. Сохраните согласованную резервную копию БД и файлов CRM. Проверьте версию 8.4 и доступность
   штатного менеджера модулей. Начните с тестовой копии вашей установки.
2. Откройте «Настройки → Менеджер модулей → Импорт модуля», выберите установочный ZIP,
   проверьте имя **ModernUI** и версию **1.0.0**, подтвердите импорт.
3. Откройте «Настройки → Другие настройки → ModernUI».
4. Включите тему для себя в пилотном режиме, откройте рабочий список, карточку и форму.
   После проверки расширьте пилот пользователями/ролями или включите тему для всех.

На первой установке тема выключена для всех. npm, Node, Composer, Phinx и консоль не нужны
для установки модуля. ZIP содержит JS/CSS, шрифты, PHP, шаблоны, переводы и лицензии зависимостей.
Ресурсы загружаются из вашей CRM; доступ к CDN и облачному образцу не нужен.

Адреса ниже относительны к корню **вашей** CRM, включая подкаталог при его наличии:

| Страница | Адрес |
|---|---|
| Настройки | `index.php?module=ModernUI&parent=Settings&view=Index` |
| Личные предпочтения | `index.php?module=ModernUI&view=Preferences` |
| Стандартный вид текущей сессии | `index.php?modernui=off` |
| Выход из безопасного режима | `index.php?modernui=on` |
| Серверная страница восстановления | `index.php?module=ModernUI&parent=Settings&view=Index&editor=off&modernui=off` |

Безопасный режим не отменяет вход, CSRF или права. Других пользователей он не переключает.

## Оформление, меню и личные предпочтения

В редакторе сначала выберите общую или ролевую область. Настройте цвет, плотность, размер текста,
шрифт, логотип и надпись. Предпросмотр действует до сохранения; кнопка отмены сохраняет прежние
значения. У каждого значения показан источник: по умолчанию, общее, роль или личное.

В разделе меню можно менять группы, порядок, подписи RU/EN/DE и значки, скрывать пункты и
возвращать их. Есть клавиатурные кнопки перемещения. Проверьте результат в настоящем мега-меню.
Новые модули появляются по правам CRM; скрытие пункта не меняет право доступа.

Личные предпочтения меняют язык темы, разрешённое оформление, избранное и компактный вид
только для текущего пользователя. «Как в CRM» снимает личный выбор языка. Даты, валюты и
языковые настройки профиля CRM не изменяются.

«Импорт и экспорт» переносит проверяемый JSON общих/ролевых настроек с предварительным
просмотром. Неизвестные модули/роли перечисляются перед применением. Режим включения переносится
только при отдельной отметке. Логотип, личные настройки, числовые ID и данные CRM не экспортируются.

Страницы входа устанавливаются отдельно кнопкой администратора «Обслуживание → Применить
страницы входа». Она меняет только два native-шаблона с резервированием и возвратом;
обычный импорт ZIP их не меняет. См. [auth-pages.md](auth-pages.md).

## Обновление, резервирование и восстановление

Перед обновлением сохраните прежний ZIP и его SHA, полную согласованную копию БД/файлов и JSON
конфигурации ModernUI. Собственные данные включают таблицы `vtiger_modernui_meta` и
`vtiger_modernui_settings`, файлы `test/logo/modernui_*.png` и, если установлены страницы входа,
`test/modernui-auth/state.php` вместе с двумя текущими шаблонами. JSON конфигурации не заменяет
backup всех личных настроек и избранного. Не публикуйте backup, он может содержать частные данные.

Загрузите новый ZIP тем же менеджером модулей и выберите обновление. Миграции пакета выполняются
автоматически и идемпотентно; сохранённые настройки не сбрасываются. После обновления проверьте
версию/состояние в «Обслуживании», обычного пользователя и возврат к стандартному виду.

Если JS не загрузился, откройте серверный адрес восстановления из таблицы выше. Если update
прерван или файлов не хватает, повторно импортируйте **полный тот же ZIP**, затем нажмите
«Восстановить» на серверной странице. Она не требует Vue. Если ошибка остаётся, отключите
ModernUI штатным переключателем менеджера модулей и проверьте журнал PHP вашей CRM.

Миграции вниз нет. Старый код с более новой схемой безопасно оставляет тему выключенной.
Полный откат — восстановление согласованной пары БД и файлов, сначала на изолированной копии;
не перезаписывайте новые рабочие записи старым backup без отдельного решения.

## Отключение и удаление

Для личного возврата используйте «Стандартный вид». Администратор может выключить тему глобально
в её настройках или выключить модуль в менеджере модулей. При этом данные настроек сохраняются.

В Open Source 8.4.0 менеджер модулей не предоставляет полного удаления extension. Для удаления
используется штатная консоль vtlib, от пользователя сервера CRM и из её корня:

```bash
php -d auto_prepend_file=vendor/autoload.php vtlib/tools/console.php --remove=ModernUI
```

Сначала верните страницы входа соседней кнопкой в «Обслуживании», если они установлены.
После успешного удаления регистрации удалите только файлы ModernUI по `dev/crm-mounts.txt`
и отчёту установочного ZIP. Ядро само их не удаляет; при оставшемся каталоге предлагает update
вместо новой установки. На dev-стенде команды `task crm:uninstall` и `task crm:unlink` управляют
регистрацией и подключением отдельно. `task crm:uninstall -- --purge` дополнительно удаляет
таблицы и логотипы ModernUI; используйте только после backup. Без purge таблицы сохраняются.
Повторная установка сохраняет настройки, но снова выключает тему.

## Сборка из исходного архива

Нужны Node 24/npm, Python 3.10+ и go-task 3. Для полного lint/test нужны PHP 8.4/8.5 CLI и Docker
для PHP 8.1/MySQL. Подробности — [DEVELOPMENT.md](DEVELOPMENT.md).

```bash
unzip ModernUI-source-1.0.0.zip
cd ModernUI-source-1.0.0
task release
```

`task release` дважды копирует только разрешённые исходники в новые временные каталоги,
в каждом выполняет `npm ci --ignore-scripts` по lockfile и production build, затем сравнивает
**оба ZIP целиком**. Время ZIP закреплено в `packaging/release.json`, порядок файлов, права и
сжатие нормализованы. Симлинки, зависимости, `.env`, частные журналы, runtime и CRM в архивы
не входят. Исходный архив содержит только публичные синтетические visual fixtures.

Для обычной разработки — `task fe:install`, `task build`, `task lint`, `task test`, `task package`.
Без `.git` PHP lint также проверяет реальные файлы. `task test:package` требует отдельный
официальный checkout Vtiger 8.4 в `VTIGER_SRC_REPO`: он не включён в исходный ZIP.
Контроль приватности мейнтейнера — `task privacy`; без локального `PRIVATE.md` он честно сообщает
об отсутствии шаблонов и не заменяет проверку секретов.

## DEV: подключение исходников

Скопируйте `.env.example` в `.env`, задайте `CRM_ROOT`, `CRM_URL` и параметры тестовой учётной
записи. Пароли и адреса держите только локально. На установке должна быть Vtiger 8.4.

```bash
task crm:link -- --force
task crm:status
task dev
# В другом терминале, когда нужно отключить исходники:
task crm:unlink
```

Карта `dev/crm-mounts.txt` подключает четыре каталога ModernUI read-only; языки используют
PHP-заглушки с require. PHP/Smarty/словари видны после обновления страницы, Vue/CSS — после
пересборки watcher. Редактируются исходники этого репозитория. Симлинки в CRM не подходят из-за
её проверки `realpath`; ручное копирование файлов не требуется. Регистрация после пустой БД —
`task crm:install`; изменения схемы/регистрации — `task crm:update`.

Для PACKAGE сначала `task crm:unlink`, затем ZIP через менеджер модулей; вместе это делает
`task crm:import-zip -- dist/ModernUI-1.0.0.zip`. После проверки верните `task crm:link -- --force`.
Для смены стенда: unlink → изменить `.env` → link. Не устанавливайте ZIP поверх read-only mounts.

## Расширения и визуальные отличия

Проверенные публичные расширения и сценарии перечислены в [compatibility.md](compatibility.md#57-проверка-на-dev-стенде-этап-08-2026-11-06)
и [regression-lifecycle.md](regression-lifecycle.md). Основные: PDF Maker 4.60 (реальный PDF),
Conditional Layouts 1.0.0 (динамические поля и inline/overlay), Advanced Custom Fields 1.0.0,
Related Blocks & Lists 1.1.0, Listview Colors 1.0, CRMTiger 1.3.12, vtDigiSign 1.0 (сохранённая
подпись), публичные расширения SalesPlatform. Их код не входит в ZIP. Отключённые расширения,
Installer с внешним сервером поставщика и произвольные новые версии не объявлены проверенными.
Специфичные настройки конкретной установки поставляются отдельно от общего пакета.

Допустимые отличия от SaaS перечислены по областям в [visual-acceptance.md](visual-acceptance.md)
и [design.md](design.md): native поля, действия, Summary и расчёты Open Source; дополнительные
действия/теги прямой карточки; собственные FullCalendar/gridster/редакторы; отсутствие SaaS AI,
рекламы и trial-баннера; открытые значки вместо коммерческих иллюстраций; согласованные исключения
фокуса/доступности. У страницы ModernUI нет облачного аналога — сравниваются компоненты той же роли.
Это не исключение для каркаса шапки, списков или открытия карточки: они проверяются отдельно.

## Приёмка

Все результаты ниже относятся к установочному `ModernUI-1.0.0.zip`:

```text
SHA-256: 4c1d7ac97819802105229f9506a6a1abaf9c7517371bf7e9b2c7fecec3933dbb
Размер: 837202 байта; 90 файлов в ZIP, 89 устанавливаемых файлов и manifest.xml.
```

Две новые официальные 8.4.0 установлены штатным установщиком в отдельном временном проекте
с новыми базами/volumes: PHP 8.1 в корне сайта и PHP 8.5 в подкаталоге. До импорта ModernUI
не была зарегистрирована; пакет импортирован из интерфейса менеджера модулей. Тот же ZIP
проверен на dev-стенде в PACKAGE. Все 89 установленных файлов совпали с архивом на каждом
стенде; подключённых исходников во время PACKAGE-проверок не было.

| Проверка финального ZIP | Dev | Чистая PHP 8.1 | Чистая PHP 8.5 |
|---|---:|---:|---:|
| F: успешные уникальные сценарии | 171 | 221 | 221 |
| Объяснённые пропуски | 22 | 7 | 7 |
| CRUD на RU/EN/DE, OFF/ON, входит в F | 6 | 6 | 6 |
| Chromium/Firefox/WebKit, входит в F | — | 12 | 12 |
| V: облачные состояния V01–V12 | 58 | 58 | 58 |
| V: успешные геометрические проверки | 1137 | 1137 | 1137 |
| Синтетическая регрессия принятого вида | — | 50/50 | 50/50 |

F сравнивает с той же CRM без темы: списки, меню, карточки, формы, расчёты/поля/документы,
системные настройки, редактор ModernUI, личные предпочтения, импорт/экспорт, ошибки, права,
безопасность/доступность и специальные экраны. Новый `task test:release` создаёт, читает,
изменяет и удаляет синтетическую запись на каждом из трёх языков в OFF и ON; сохранённые
значения дополнительно читаются в стандартном интерфейсе. На чистых проверены включение,
пилот, отключение и возврат к стандартному виду без CDN/облачной CRM.

На dev пропущены изменения ролей/полей/списков/процессов, добавление виджета, загрузка логотипа
и сценарии с синтетическими пользователями чистого стенда. На чистых отсутствуют PDF Maker,
профили условных полей и подписи; эти функции проверены на dev. Отправка письма восстановления
пароля не повторялась в релизном прогоне: её отдельная проверка с почтовой ловушкой остаётся
в отчёте этапа 20. Пропуски не засчитаны как PASS.

V выполнена отдельно от F: закреплённые облачные эталоны и принятые синтетические снимки
сохранены без изменения порогов и масок. Облако, чистый стенд и dev дополнительно осмотрены
в пользовательском Chrome через Playwriter: шапка/меню, списки, карточка, форма и настройки;
dev также на 1024/412 px. Разрешённые отличия перечислены выше, открытых блокирующих
визуальных замечаний в проверенной матрице нет.

Длительные обёртки некоторых запусков завершались SIGTERM; успешные результаты сохранены,
оставшиеся тесты пройдены отдельными группами. Итог сопоставлен с полным списком ожидаемых
тестов: нет потерянных сценариев и двойного подсчёта подготовки/входа. Ошибки подготовки
(пустой dashboard новой CRM и запуск зависимого теста без его фикстуры) исправлены в составе
прогона, исходные журналы сохранены. Неожиданных отказов в итоговой матрице нет.

Lint: 72 PHP-файла × 8.1/8.4/8.5, typecheck, ESLint и ES5 loader — PASS. PHP unit 55×3,
MySQL 40×2 кодировки, перенос конфигурации 45, frontend 84, пакет 930 — PASS. npm audit — 0.
В проверенном окне PACKAGE журналы PHP не содержат сообщений с источником в ModernUI;
известные ошибки ядра/сторонних расширений отделены от ошибок темы.

Сборка выполнена дважды в независимых чистых каталогах по lockfile: оба ZIP побайтово
совпали. Исходный ZIP затем распакован без `.git`, и `task release` воспроизвёл оба архива;
PHP lint из такой распаковки тоже прошёл. SHA-256, версии инструментов и инвентаризация
приложены к релизу. Allowlist, приватные шаблоны, признаки секретов и достижимая история Git
проверены; код CRM, коммерческие исходники и частные снимки не включены.

DEV возвращён к исходникам проверенного payload: 9 проверок PHP/Smarty/RU/EN/DE/CSS/Vue/watch
прошли, build до/после совпал. Настройки/избранное восстановлены, собственные тестовые записи
удалены; 20112 отслеживаемых файлов и Git dev-CRM, по 12923 файла ядра чистых CRM неизменны.
Реальные URL редактора, предпочтений и серверного восстановления вернули HTTP 200.

Предыдущие 40 циклов стабильности, бюджеты скорости и полный upgrade/uninstall/reinstall/
аварийное восстановление остаются привязаны к прежнему ZIP в
[regression-lifecycle.md](regression-lifecycle.md). Они не объявлены повторным прогоном 1.0.0.
От последнего исправления меню 0.18.0 установочный архив отличается только `manifest.xml`.
Hosted CI по решению мейнтейнера выключен; эта приёмка локальная. Сырые результаты и частные
снимки сохранены вне публикуемых архивов.
