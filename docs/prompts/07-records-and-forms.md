# ModernUI 07 — Карточки, формы и товарные позиции

Рабочий каталог: корень этого репозитория. Прочитай `PRIVATE.md` (если есть), `AGENTS.md`, `docs/COMMON.md`, `docs/PLAN.md`, `docs/DEVELOPMENT.md`, `docs/I18N.md`,
design.md, compatibility.md и сценарии приёмки.
Предусловие: этап 06 завершён. Если этап уже начат, продолжи по журналу.

## Задача

Доведи карточки и формы до рабочего нового интерфейса, сохранив исходное поведение.
Особое внимание — SalesOrder и расширения, меняющие поля и связанные блоки.

## Выполни

1. Карточка: заголовок/действия, блоки полей, вкладки, связи, комментарии, история, документы.
   Покажи реальные возможности экземпляра; не подменяй отсутствующие в Open Source облачные блоки
   пустыми заглушками.
2. Create/edit/quick create/inline edit: подписи, обязательность, ошибки, даты/время, числа/валюты,
   checkbox, picklist/multipicklist, reference popup, autocomplete, загрузка файлов, текстовый редактор,
   сохранение/отмена.
3. Сохрани реальные input name/id, hidden/disabled/readonly, порядок событий, механизм submit и
   обработки ошибок. Без второй формы и двойного Save. Enter и повторный клик не дублируют сохранение.
4. SalesOrder/Quotes/Invoice/PurchaseOrder: товарные строки, добавление/удаление/перестановка,
   товары/услуги, скидки, налоги, валюты, итоги, связанные всплывающие окна. Визуальные изменения
   не меняют расчёт или payload.
5. На dev-стенде проверь расширения форм из обязательной матрицы (`PRIVATE.md`; например,
   ControlLayoutFields, AdvancedCustomFields, FieldAutofill, SPDynamicBlocks, RelatedBlocksLists),
   подписи и ссылки документов; сравни поля, скрытие, обязательность, связи и сохранённые значения
   с видом без темы.
6. Сценарий заказа на dev-стенде (детали — обязательная матрица `PRIVATE.md`): создание синтетического →
   заполнение → смена значений динамических полей → товарные строки → сохранение → повторное
   открытие → связанные записи → PDF/подпись, если они в матрице. Интеграции стенда отключены — проверь перед записью.
7. Несовпадение прав записи/поля, read-only пользователь, ошибка валидации, серверный отказ, истёкшая
   сессия, отмена изменений. Ошибки видимы, введённые значения не пропадают из-за перерисовки ModernUI.
8. Сравни сохранённые значения и результаты расчётов, а не только вид. Используй сценарии
   инструмента приёмки dev-стенда (`PRIVATE.md`, не меняя его) и собственные `tests/` для чистого стенда.
   Итерации — в DEV на dev-стенде; пересобери ZIP и проверь в PACKAGE на обоих стендах,
   адаптивность и фокус.
9. Все собственные подписи, ошибки и подтверждения — на RU/EN/DE. Переключение языка темы не меняет
   payload, числовые значения и локальные правила полей CRM.

## Готовность

- Список → карточка → редактирование → сохранение работает на обоих стендах.
- Формы и связи доступны по правам; динамические поля и расширения действуют.
- Товарные позиции, итоги и значения после сохранения совпадают с поведением без темы.
- Нет критических потерь функций и визуальных перекрытий; всё подтверждено сценариями.
- Три языка работают без потери введённых значений и подмены переводов чужих модулей.
