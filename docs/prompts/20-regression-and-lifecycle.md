## Задача

Докажи функциональную готовность интерфейса и переносимость установки. Исправляй найденные дефекты
в ModernUI и повторяй затронутые сценарии до выполнения критериев.

## Выполни

1. Зафиксируй кандидатную версию и SHA-256 ZIP, SHA исходников, версии обоих стендов (SHA CRM
   dev-стенда — в `PRIVATE.md`). Проверки пакета — в PACKAGE на установленном архиве без подключения
   исходников. Сверь состав пакета и неизменность файлов ядра до/после установки.
2. Чистый стенд, admin и ограниченные пользователи: меню, настройки, списки, карточки, CRUD, быстрые
   формы, связи, inventory, календарь, отчёты, документы, служебные настройки, тестовый custom module.
   Проверь установку в корень и в подкаталог.
3. dev-стенд в PACKAGE: инструмент приёмки CRM (`PRIVATE.md`, без изменения его кода) и обязательная
   матрица по ролям: динамические поля, сторонние кнопки, критические бизнес-сценарии, связанные списки,
   PDF, подпись. Сравни с ТЕМ ЖЕ состоянием стенда без темы. Записи — синтетические.
4. Жизненный цикл на тестовых данных: установка → включение одному пользователю → настройка →
   отключение → включение → обновление с предыдущего пакета → удаление → повторная установка.
   Обновление — реальным ZIP 0.6.0 → кандидат, с проверкой сохранения всех областей настроек,
   личного языка, избранного и правил меню. Если схема изменилась — исполни её миграцию и
   повторный идемпотентный запуск; не создавай фиктивную миграцию только ради теста.
5. Повторный вызов миграций/регистрации, несовместимая версия хоста, конфликт имени, отсутствующий
   asset, неуспешная миграция, прерванное обновление. Восстановление стандартного интерфейса доказано.
   Не обещай откат версии БД возвратом старых файлов: проверь отдельный runbook.
6. После disable/uninstall под обычным пользователем: нет запросов к удалённым endpoints и dangling
   global links. Чужие настройки/меню/записи не удалены. Update сохраняет theme/menu/user preferences;
   uninstall соответствует описанной политике.
7. Экспорт конфигурации из dev-стенда в чистый стенд: отсутствующие модули/роли, новые module IDs,
   обратный перенос. Права и личные данные не переносятся ошибочно.
8. Frontend build/checks, PHP по матрице (8.1 и 8.5), сценарии безопасности, консоли браузера,
   скриншоты, бюджеты скорости, доступность. Не понижай критерии и не исключай падающие модули без
   конкретного объяснения.
9. Единый отчёт: версия пакета, окружение, роль, сценарий, результат, ссылка на артефакт; отдельные
   списки исходных дефектов хоста и регрессий ModernUI. Публичный отчёт — обезличенный; результаты по
   собственным модулям конкретной CRM, секреты и данные клиентов — в `PRIVATE.md` и приватный каталог.
10. Собственные страницы/настройки/диалоги на RU/EN/DE, выбор языка, fallback, локализованные подписи
    меню, JSON-перенос. Выбор языка темы не меняет форматы полей и значения CRM.
11. Отдельно DEV: `task crm:link` → правки PHP/Smarty/Vue/CSS/перевода → результат на dev-стенде →
    синтетическая запись → `task crm:unlink` → `task crm:link`. Докажи, что `git status` и
    отслеживаемые файлы CRM не изменились из-за темы, в базе — только ModernUI и записи сценария.
    Не заменяй этот сценарий проверкой ZIP и наоборот. В конце DEV снова подключён. `task privacy`.
12. На том же hash ZIP повтори V01–V12: default-профиль, обновлённый профиль, новый пользователь,
    admin/restricted, список/overlay/прямой Detail/Edit, системные настройки. Результат содержит
    отдельные колонки V и F. `full`/`islands` не означает прохождение V. Исправление любой ошибки
    даёт новую сборку и повтор затронутых проверок; разные архивы не складываются в один PASS.
13. Проверь публичные GitHub Actions: обязательные сборка, тесты, privacy и визуальная регрессия
    на синтетическом чистом стенде действительно работают на проверяемой ревизии. Локальный
    прогон обозначай локальным; без разрешения пользователя ничего не пушь. Если для нового
    SHA hosted CI ещё не запускался, не выдавай прежний зелёный запуск за новый и укажи эту
    границу отдельно. Отсутствие нового hosted запуска само по себе не разрешает публикацию.

## Готовность

- Обязательные сценарии проходят на чистом стенде и dev-стенде; необъяснённых изменений данных,
  расчётов, прав и функций нет.
- Lifecycle и обновление настроек доказаны реальными пакетами; ядро не меняется.
- RU/EN/DE, немедленное обновление DEV и невмешательство в git CRM проверены независимо от PACKAGE.
- Все ограничения конкретны. Пропущенный обязательный стенд/роль/сценарий означает «НЕ ЗАВЕРШЁН»,
  даже если сборка и скриншоты выглядят хорошо.
- Визуальная приёмка 18 сохранена после update и на конечном кандидате; V/F привязаны к ZIP.

«ModernUI 20: ЗАВЕРШЁН» либо «ModernUI 20: НЕ ЗАВЕРШЁН — запустите этот же промпт снова».
