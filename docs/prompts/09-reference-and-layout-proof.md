# ModernUI 09 — Закреплённый эталон и доказательство новой компоновки

Рабочий каталог — корень этого репозитория. Прочитай `PRIVATE.md`, `AGENTS.md`, `docs/COMMON.md`,
`docs/PLAN.md`, `docs/DEVELOPMENT.md`, `docs/I18N.md`, `docs/ui-audit.md`, `docs/visual-parity.md`,
`docs/design.md`, `docs/architecture.md`, `docs/compatibility.md` и `docs/verification.md`.
Предусловие: реализованы этапы 01–08. Продолжай по журналу; выполняй только этап 09.

## Результат

Зафиксированный текущий облачный образец и небольшой работающий прототип, который доказывает,
что требуемая компоновка достижима переносимым модулем без потери поведения Vtiger. Аудит
`ui-audit.md` уже выполнен: дополни отсутствующие замеры и проверь рискованные механизмы,
не трать этап на повторение общего исследования или переписывание всего frontend.

## Выполни

1. Подтверди `task crm:status`, активную тему/сборку в браузере и Git обоих проектов. Отсутствующие
   после перезагрузки подключения восстанавливаются `task crm:link`; вид без загруженной темы
   нельзя записывать как дефект оформления ModernUI. Сохрани исходные настройки.
2. Прочитай skill Playwriter и осмотри живое облако в Chrome. По `visual-parity.md` §3–5 закрепи
   набор V01–V12: состояния, снимки, измерения, язык, viewport, маски и приватный манифест с хэшами.
   Обязательно: list, открытое меню, Summary, Details, edit/create, quick create, inventory,
   общий каталог настроек и хотя бы одна вложенная настройка. Недоступные возможности явно отметь.
3. Обнови целевые разделы `design.md`: реальные токены, композицию и состояния. Составь реестр
   расхождений по ID с этапом исправления. Для каждого измерения укажи облачный элемент и метод.
   Не переноси Inter, геометрию v7 или старую палитру в новый эталон только потому, что они уже в коде.
4. Проверь по коду чистой 8.4 и dev-стенда точки интеграции: шапка/меню, фильтр списка, штатный
   quick view/overlay, Detail/Edit, AJAX, модальные, делегированные события и teardown. Сопоставь
   CSS reflow, адаптер исходных узлов и штатные механизмы загрузки. Зафиксируй выбранный вариант
   в новом решении `architecture.md`; ограничения A2/A6 пересмотри по `visual-parity.md` §1.
5. Реализуй узкий прототип на одном стандартном модуле (Accounts или Contacts): шапка без
   постоянной глобальной полосы; список → настоящая карточка поверх списка → закрытие с
   восстановлением фильтра/страницы/прокрутки; прямая ссылка на эту же запись. Затем настоящая
   форма: штатная валидация, отмена и одно сохранение синтетической записи. Нужны рабочие
   handlers, а не изображение подложки, iframe, статический HTML или второй CRUD.
6. Прототип включай только в своей тестовой области/на поддержанном экране, с рабочим возвратом
   в стандартный вид. Проверь двойное открытие, повторную AJAX-загрузку, Back/Forward, вложенный
   popup, Escape/focus и аварийный отказ. На dev-стенде проверь сохранность действий расширений.
   Перед записью соблюдай проверку интеграций из `PRIVATE.md`.
7. Собери ZIP прототипа; воспроизведи короткий сценарий в PACKAGE на чистой 8.4 (оба PHP/пути)
   и dev-стенде. Сравни запросы/значения с v7, хэши ядра и отсутствие дублирующихся обработчиков.
   После PACKAGE верни DEV. Прототип должен стать основой последующих этапов, не отдельным демо.
8. Введи пригодный для следующих сессий способ собирать пары и таблицу геометрии. Пока допустим
   небольшой локальный инструмент/манифест, без доступа к облаку из CI. Измерь шум повторных снимков
   эталона и назначь пороги для сопоставимых областей; проверь, что лишняя боковая панель их нарушает.

## Готовность

- Образец доступен следующему агенту: файлы существуют, хэши проверены; нет смешения версий облака.
- Для всех V01–V12 есть цель, свидетельство или честно названный пробел, владелец-этап и метод проверки.
  Нельзя пропустить ключевые список/карточку/форму/настройки и объявить эталон достаточным.
- Прототип доказал способ интеграции на обоих типах стендов; runtime и core не подменены.
- Если обязательная облачная компоновка не достигнута, зафиксированы точный blocker и проверенные
  альтернативы. Этап остаётся незавершённым; решение «оставим старую карточку» не принимается молча.
- Архитектура, дизайн, V/F-результаты, приватные материалы и журнал согласованы, `task privacy` чист.
