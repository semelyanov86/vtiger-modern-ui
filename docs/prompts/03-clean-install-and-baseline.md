# ModernUI 03 — Чистая Vtiger 8.4, установка ZIP и цикл разработки

Рабочий каталог: корень этого репозитория. Прочитай `PRIVATE.md` (если есть), `AGENTS.md`,
`docs/COMMON.md`, `docs/PLAN.md`, `docs/DEVELOPMENT.md`, `docs/I18N.md`, architecture.md и compatibility.md.
Предусловие: этап 02 завершён, ZIP собран, модуль зарегистрирован на dev-стенде.
Если этап уже начат, продолжи по журналу.

## Задача

Подними отдельную свежую официальную Vtiger 8.4 (чистый стенд) и докажи на ней установку ZIP штатным
менеджером. Проверь тот же ZIP на dev-стенде без подключённых исходников. Сними исходное поведение
без темы. Докажи, что цикл «правка → результат на dev-стенде» работает для всех типов файлов.

## Выполни

1. `task crm:status`: стенд, версия, подключение, регистрация. Сними `git status` CRM — эталон для
   проверки невмешательства.
2. Чистый стенд по `DEVELOPMENT.md`: Docker-проект в `dev/` с закреплёнными образами, официальный релиз
   8.4.0 или тег `8.4.0` с записанной контрольной суммой/SHA, новая пустая база, штатный установщик,
   PHP 8.1 (и 8.5, если реализуемо), свой адрес и почтовая ловушка. Без дампа и патчей dev-стенда, без
   подключения `src/`, watcher и Vite. Команды up/down/status/reset — в `Taskfile.yml` и `README.md`;
   данные — в собственных volumes; секреты — в `.env`, не в git.
3. На чистом стенде создай синтетические данные и роли: администратор, пользователь с ограниченными
   модулями/записями/полями. Штатно добавь простой тестовый custom entity-модуль, чтобы доказать
   отсутствие в ModernUI списка разрешённых имён.
4. Сними исходное поведение без темы на обоих стендах: вход, меню, Accounts/Contacts/Leads,
   SalesOrder и товарные позиции, связанные списки, календарь/отчёты, настройки, запрещённые URL.
   Зафиксируй ошибки исходной системы (известные ошибки dev-стенда — `PRIVATE.md`) и хэши файлов
   ядра чистого стенда.
5. Импортируй ZIP этапа 02 в чистый стенд через «Настройки → Менеджер модулей → Импорт». Не распаковывай
   вручную, не исправляй БД после установки. Проверь настройки, включение для одного пользователя,
   отсутствие влияния на другого, disable/enable и стандартный вид. Хэши ядра не изменились,
   лишних глобальных ссылок нет.
6. PACKAGE на dev-стенде: `task crm:unlink` → тот же ZIP через менеджер модулей (как обновление уже
   зарегистрированного модуля, а при необходимости — после штатного удаления) → проверки → возврат в
   DEV `task crm:link -- --force`. Убедись, что в PACKAGE нет заглушек, подключений и dev URL.
7. Ошибки исправляй в ИСХОДНИКАХ ModernUI, пересобирай ZIP и повторяй установку штатно. Не «чини»
   чистую Vtiger патчами.
8. Докажи цикл разработки на dev-стенде четырьмя реальными временными правками: PHP, Smarty,
   Vue/CSS (через watcher), перевод. Каждая видна после перезагрузки без копирования и переустановки
   ZIP; запиши время. Проверь ошибку компиляции watcher'а и восстановление. Верни правки.
9. Докажи невмешательство: `git status` CRM не изменился; подключённые каталоги read-only в namespace
   PHP-FPM; синтетическая запись сценария есть только в базе стенда; в базе — только регистрации и
   таблицы ModernUI.
10. Подготовь независимые Playwright-сценарии (`tests/`) для чистого стенда и dev-стенда: параметры URL,
    роли, языки, тестовые данные из `.env`; пароли не в git. Проверь RU/EN/DE текстов модуля, включая
    английский fallback на чистой `en_us`.
11. Запиши environments.md (команды, mount map, режимы, источник 8.4.0 и его SHA) и verification.md
    (фактически пройденные проверки) — обезличенно; адреса, пути и SHA CRM — в `PRIVATE.md`.
    В конце оставь DEV на dev-стенде подключённым и рабочим. `task privacy`.

## Готовность

- Есть свежая официальная CRM с новой базой и доказательство реального импорта ZIP.
- Тот же ZIP проверен на dev-стенде без подключения, затем DEV восстановлен.
- Правки PHP/Smarty/Vue/CSS/перевода видны на dev-стенде сразу; git CRM не изменён.
- Foundation работает у администратора и обычного пользователя; отключение возвращает прежний
  интерфейс без изменения ядра.
- Стенды воспроизводимы и безопасны для сценариев записи; в verification.md — только фактически
  пройденные проверки. Копия dev-стенда вместо чистой установки или подключение вместо импорта ZIP
  критериям не удовлетворяют.

Заверши по `docs/COMMON.md`. Последняя строка: ModernUI 03: ЗАВЕРШЁН либо НЕ ЗАВЕРШЁН.
