# ModernUI 21 — Релизный ZIP и работающий интерфейс

Рабочий каталог: корень этого репозитория. Прочитай `PRIVATE.md` (если есть), `AGENTS.md`,
`docs/COMMON.md`, `docs/PLAN.md`, `docs/DEVELOPMENT.md`, `docs/I18N.md`, `docs/visual-parity.md`,
отчёты этапов 18–20 и compatibility.md.
Предусловие: этап 20 завершён. Рабочие серверы не трогать, ничего не публиковать и не пушить.
Если этап уже начат, продолжи по журналу.

## Задача

Выпусти законченный проверенный модуль: установочный ZIP, исходники, инструкция, работающий новый
интерфейс RU/EN/DE и настройки, а также готовое окружение разработки на dev-стенде.
Один исходный каталог или успешная dev-сборка результатом не являются.

## Выполни

1. Зафиксируй релизную версию и собери из чистого временного каталога с lockfile:
   `ModernUI-<version>.zip` и `ModernUI-source-<version>.zip` в `dist/`. В исходном архиве — инструкции
   сборки. Установочный архив содержит production assets, PHP, собственные шаблоны/переводы и notices.
2. Проверь архивы по allowlist: нет `.env`, `PRIVATE.md`, `USAGE.md`, credentials, данных/скриншотов
   клиентов, node_modules, `.local/`, runtime/volumes, целого Vtiger, коммерческих модулей и зависимостей
   от конкретной установки. Исходный архив включает dev-скрипты без частных данных; установочный ZIP не
   содержит dev endpoints/URL. `task privacy` чист, история git проверена на частную информацию.
   Сохрани SHA-256 и отчёт файлов. Повторная сборка даёт тот же runtime; различия ZIP-метаданных
   нормализуй или точно объясни.
3. Подними ЕЩЁ ОДНУ свежую официальную Vtiger 8.4 с новой базой (команды этапа 03, новый volume).
   Никакой ранее установленной ModernUI, ручных таблиц, дампа и патчей dev-стенда.
4. Из интерфейса менеджера модулей импортируй релизный ZIP как обычный администратор. После подготовки
   CRM не используй npm/Phinx/Composer/CLI для установки модуля. Проверь включение, оформление, редактор
   меню, сохранение, личные предпочтения, импорт/экспорт, стандартный вид, отключение и короткий
   CRUD-сценарий на RU/EN/DE. Запуск не требует доступа к CDN или облачной CRM.
5. Тот же финальный ZIP — на dev-стенде в PACKAGE (`task crm:unlink`, импорт через менеджер модулей).
   Проверь сценарии и возможность вернуться к стандартному виду. Не устанавливай модуль на установки
   не 8.4 и на серверы, запрещённые в `PRIVATE.md`; не меняй git CRM.
6. Верни DEV: `task crm:link -- --force` с исходниками ровно проверенной версии, при необходимости
   `task crm:update`. Проверь watcher, подключение, список/карточку/форму заказа, настройки и три языка.
   Включи тему тестовому пользователю только в базе стенда, зафиксируй вход (без пароля в отчёте) и
   команды `task crm:status` / `task crm:unlink`.
7. `docs/release.md` и `README.md` — понятная инструкция: поддерживаемые/проверенные версии; загрузка ZIP;
   включение; настройка темы/меню; личные предпочтения; обновление с сохранением настроек;
   отключение/удаление; резервирование собственных настроек/файлов; восстановление при поломке
   JS/обновления; сборка разработчиком; языки и границы перевода; DEV (link/unlink/status/watch,
   mount map, смена стенда через `.env`); ограничения и матрица проверенных публичных расширений.
8. Если для конкретной CRM нужен опциональный профиль/адаптер, поставь его отдельно и опиши в
   `PRIVATE.md`. Докажи, что основной ZIP без него работает на чистом стенде.
9. Обнови итоговые статусы и журнал (обезличенно; частное — в `PRIVATE.md`). Перед ответом проверь
   существование и хэши названных файлов, реальные URL настроек/восстановления и доступность
   локального UI.
10. Подтверди отдельность git темы, отсутствие кода CRM и частных данных в её истории и архивах,
    отсутствие изменений в git CRM и работу всех переводов из ZIP без подключения исходников.
11. На свежей установке и dev-стенде проверь визуально V01–V12 именно релизного ZIP: шапка,
    меню, списки, облачная карточка/форма, системные настройки и настройки темы. Сопоставь с
    принятым результатом 18 и ссылками на облачный эталон. Релиз не закрывает остаточные
    визуальные дефекты словами «совместимость со старым интерфейсом». Частные снимки не
    включай в архивы; публичные иллюстрации — только синтетический чистый стенд.

## Готовность

- Есть конечный ZIP, который реально установился на новую официальную Vtiger 8.4 и на dev-стенд.
- Есть исходники и воспроизводимая сборка, точные версии, SHA-256 и документация.
- На dev-стенде работает DEV с быстрым обновлением исходников. Интерфейс и настройки темы переведены
  на RU/EN/DE, PACKAGE проверен отдельно.
- Git CRM и рабочие серверы не менялись; в публикуемых файлах нет частной информации.
- Нет незавершённых обязательных этапов, заглушек и известных блокирующих регрессий.
- Обе проверки V/F пройдены для финального ZIP; все допустимые визуальные отличия перечислены,
  не спрятаны в общей оговорке о v7.

В ответе дай пути архивов, инструкцию, адреса настроек и dev-стенда, команды link/unlink/status/watch,
сводку проверок и языков, точные ограничения совместимости. Не обещай совместимость с любым
неизвестным расширением. Заверши по `docs/COMMON.md`.
