# ModernUI 14 — Создание, редактирование и товарные позиции

Рабочий каталог — корень репозитория. Прочитай `PRIVATE.md` (если есть), `AGENTS.md`,

design.md, architecture.md, compatibility.md и прототип этапа 09.
Предусловие: этап 13 завершён. Если этап начат — продолжай по журналу.

## Задача

Реализуй V07–V08: облачную композицию настоящих форм создания, редактирования и быстрого
создания, включая inventory. Сохранение и расчёты выполняет существующая CRM.

## Выполни

1. Сверь с облаком Edit/Create/Quick Create, reference picker, ошибки и нижние действия.
   Повтори большую оболочку формы, заголовок, контекстный список секций, поля/карточки на
   светлой поверхности, две колонки и закреплённое основное действие справа. Для Quick Create
   используй именно его референс; не растягивай любую короткую форму до размера полной.
2. Используй реальную форму CRM с сохранением ID/name, CSRF, uitype, required, disabled,
   зависимостей и обработчиков. Обёртки/адаптеры только по доказанному в 09 контракту.
   Не сериализуй форму заново через общий API и не переписывай вычисления/валидацию.
3. Все типы полей: текст/textarea, дата/время, числа/валюта, checkbox, select/multiselect,
   владелец, relation picker, загрузка файла, rich text; поля расширений из матрицы. Popup,
   Select2 и календарь не обрезаются, находятся над нужным окном, корректно закрываются.
4. Ошибка обязательного/условного поля показывает понятное сообщение и переводит к секции
   с ошибкой; скрытые поля не становятся видимыми через поиск. Save pending, двойной клик,
   серверная ошибка, отмена, переход с несохранёнными изменениями и повторная отправка не
   теряют введённые значения и не создают дубль. Фокус возвращается в карточку/список.
5. Inventory: товары/услуги, добавление/удаление/перестановка строк, количество, цена,
   скидки, налоги, доставка, валюта, итоги. Сравни исходные значения, запрос и сохранённый
   результат с v7; проверь расчёты минимум на двух строках с разными налогами/скидками.
   Длинную таблицу допускается прокручивать внутри области; footer не закрывает итог/ошибку.
6. Создание из списка, Edit из карточки, duplicate, quick create и прямая ссылка Edit:
   успешное сохранение открывает ожидаемый результат, отмена возвращает правильный контекст.
   Не переопределяй специальный сценарий модуля универсальным редиректом.
7. Синтетические CRUD-сценарии типового модуля, inventory и custom module с динамическими
   полями/расширениями; права admin/restricted. Перед записью проверь изоляцию интеграций
   по PRIVATE. При необходимости облачных данных используй только синтетические записи.
8. RU/EN/DE, клавиатура, zoom, все ширины, затем парные снимки V07–V08. Тесты проверяют
   реальное поведение и данные, а не прежние координаты или порядок визуальных обёрток v7.
   PACKAGE на обоих стендах, возврат DEV, документация, журнал и privacy.

## Готовность

- Create/Edit/Quick Create имеют проверенную облачную геометрию; старая форма внутри новой
  рамки без изменения её композиции не засчитывается.
- Поля, ошибки, отмена, сохранение, динамические зависимости и inventory не регрессировали;
  расчёты подтверждены сохранёнными значениями и сопоставлением с v7.
- V07–V08/F закрыты без P0/P1, на узких экранах все действия достижимы.
