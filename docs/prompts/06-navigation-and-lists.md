## Задача

Преврати основу темы в рабочую навигацию и интерфейс списков. Настройки меню управляют реальными
переходами, существующие функции списков сохраняются.

## Выполни

1. Оболочка из design.md: шапка, переключение разделов, меню, избранное, поиск модулей, компактное
   состояние, адаптация узкого экрана. Данные текущего экземпляра и права пользователя; никаких
   списков модулей/доменов/ID под конкретную установку.
2. Сохрани глобальный поиск, быстрое создание, профиль, выход, настройки, штатные уведомления и
   элементы расширений, которые реально есть в CRM. Поведение — через штатные механизмы, без
   фиктивных облачных функций. На dev-стенде проверь элементы шапки из обязательной матрицы
   (`PRIVATE.md`) и сторонние HEADERSCRIPT/HEADERLINK.
3. Меню не перехватывает несовместимые маршруты и не ломает back/forward, открытие в новой вкладке,
   прямую ссылку, обновление страницы и путь в подкаталоге. SPA router поверх штатной навигации не вводи.
4. Списки Leads/Contacts/Accounts и SalesOrder, плюс тестовый custom module: заголовок, панель действий,
   фильтры, поиск, таблица, сортировка, пагинация, выбор строк, массовые действия, загрузка, пустой
   список и ошибки.
5. Сохрани существующую таблицу и её события там, где на неё опираются модули. Не делай второй
   независимый выбор строк/фильтров и не заменяй HTML серверной таблицы Vue-рендером без доказанного
   сохранения всех контрактов.
6. Проверь ListviewColors/VGS и пользовательские поля/ссылки/цвета. Меню действий и чекбоксы работают
   после поиска, смены фильтра и AJAX-перезагрузки. Контекст сохраняется, нет двойных запросов/обработчиков.
7. Последовательности: фильтр → сортировка → выбор нескольких строк → действие → возврат в список;
   поиск → карточка → назад; popup выбора записи. Массовые изменения — только на синтетических данных.
8. Проверь на чистом стенде и dev-стенде под ограниченными ролями, на RU/EN/DE, с длинными немецкими/
   русскими названиями и на узких экранах. Итерации — в DEV на dev-стенде, ZIP — в PACKAGE на обоих
   стендах (dev-стенд после `task crm:unlink`, затем возврат в DEV). Скриншоты с данными клиентов —
   только в приватный каталог из `PRIVATE.md`; результаты — в verification.md.

## Готовность

- Пользователь работает с меню и списками без возврата к скрытым старым кнопкам.
- Все существовавшие действия доступны по правам, расширения не потеряли свои элементы.
- Настройки меню применяются, новый/удалённый модуль обрабатывается корректно.
- Поиск, фильтры, выделение и навигация проверены после повторных AJAX-переходов.
- Собственные тексты навигации/списков и accessibility labels переведены на RU/EN/DE.
