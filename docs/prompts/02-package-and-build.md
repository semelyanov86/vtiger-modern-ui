# ModernUI 02 — Установочный пакет, сборка Vue и регистрация на dev-стенде

Рабочий каталог: корень этого репозитория. Прочитай `PRIVATE.md` (если есть), `AGENTS.md`,
`docs/COMMON.md`, `docs/PLAN.md`, `docs/DEVELOPMENT.md`, `docs/I18N.md`, `docs/RESEARCH.md`
и результаты этапа 01 (architecture.md, settings.md, dependencies.md, design.md).
Предусловие: этап 01 завершён. Если этап уже начат, продолжи по журналу.

## Задача

Реализуй самостоятельный extension-модуль и настоящий импортируемый ZIP с production-сборкой Vue 3.
Нужен работающий фундамент: загрузка, собственные настройки, включение/отключение, восстановление.
Модуль должен быть зарегистрирован на dev-стенде штатным lifecycle и работать там из подключённых
исходников. Полный интерфейс последующих этапов не имитируй.

## Выполни

1. Создай `src/`, `frontend/`, `packaging/`, `tests/` по принятой структуре. Файлы `src/` лежат по
   путям CRM (`dev/crm-mounts.txt`). Не размещай изменённые копии Vtiger/Users/Header.tpl/JSResources.tpl
   в пакете и не создавай файлов в репозитории CRM.
2. manifest.xml и класс модуля с `vtlib_handler`. Install/update/enable/disable/uninstall идемпотентны,
   управляют только своими ссылками и настройками. Глобальные регистрации работают у ограниченного
   пользователя, но не раскрывают административные API.
3. Версионированное хранилище конфигурации и миграции внутри пакета. Повторный вызов не создаёт
   дубликатов, update не теряет настройки. Нет зависимости от Phinx и бизнес-таблиц.
4. Серверная страница настроек с проверкой администратора, включением темы для себя и возвратом к
   стандартному виду. Доступ к восстановлению при поломке JS. Полный редактор — этап 05.
5. Vue 3/Vite, lockfile, production build, отдельный загрузчик для `text/javascript` HEADERSCRIPT,
   manifest, локальные assets. Сохрани `window.jQuery`/`$`; не публикуй второй глобальный Vue.
   Base URL без привязки к корню сайта.
6. Контролируемый boot: авторизованная конфигурация, проверка версии и активности модуля,
   монтирование собственного контейнера, активация CSS, unmount/очистка. При ошибке остаётся
   стандартный интерфейс.
7. Команды в `Taskfile.yml` (имена можно уточнить; описать в `README.md`, `AGENTS.md`, `DEVELOPMENT.md`):
   - `build` — production-сборка в подключённый каталог `src/…` (исключён из git);
   - `dev` (watch) — автоматическая атомарная пересборка для dev-стенда (`DEVELOPMENT.md`);
   - `package` — ZIP из allowlist в `dist/`, версия и SHA-256; без node_modules, dev server, CRM, `.env`,
     `PRIVATE.md`, тестовых БД, чужих модулей и настроек стенда;
   - `crm:install` / `crm:update` — регистрация и обновление в базе стенда тем же кодом, что и
     менеджер модулей (`Vtiger_Package` import/update через CLI-обвязку в `dev/`): unlink → импорт →
     распакованные файлы в `.local/crm-replaced/` → link. Ручной SQL запрещён;
   - `lint` — добавь нижнюю границу PHP 8.1 (например, Docker-образ `php:8.1-cli`).
8. Перед первой регистрацией зафиксируй `task crm:status` (подробности — в частный журнал).
   Выполни `task crm:install`, включи тему администратору, проверь загрузку, настройки, отключение и
   стандартный вид в браузере (Playwright, учётная запись из `.env`). Другой пользователь не затронут.
   `git status` CRM не изменился.
9. Проверь пути файлов ZIP фактическим импортёром 8.4.0 (сверка с `PackageImport.php` и реальным
   импортом через `crm:install`). Полную установку на чистый стенд делает этап 03.
10. i18n-фундамент RU/EN/DE по `I18N.md`: PHP-словари, словари Vue, locale UI-библиотеки, mapping
    Vtiger, английский fallback. Базовые настройки и ошибки — на трёх языках; проверка ключей/параметров.
11. Значимые проверки генерации пакета, миграций настроек и guards; frontend build; `task lint`;
    список файлов ZIP; `task privacy`. Недоступную версию PHP не отмечай проверенной.

## Готовность

- Получен реальный ZIP с зафиксированными версией и SHA-256; в нём только собственные файлы и
  распространяемые зависимости с лицензиями.
- Модуль зарегистрирован на dev-стенде штатным lifecycle, работает из подключённых исходников;
  правка PHP и пересборка Vue видны после перезагрузки без переустановки.
- Есть действующий backend/loader/settings foundation, не пустые методы с TODO.
- Сборка повторяема; установка на чистый стенд остаётся обязательной на этапе 03.
- Базовые страницы и сообщения локализованы на три языка.
