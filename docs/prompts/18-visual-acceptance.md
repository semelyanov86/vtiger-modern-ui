# ModernUI 18 — Полная визуальная приёмка и исправление расхождений

Рабочий каталог — корень репозитория. Прочитай `PRIVATE.md` (если есть), `AGENTS.md`,
`docs/COMMON.md`, `docs/PLAN.md`, `docs/DEVELOPMENT.md`, `docs/I18N.md`, `docs/visual-parity.md`,
`docs/ui-audit.md`, design.md, compatibility.md и verification.md.
Предусловие: этап 17 завершён. Если этап начат — продолжай по журналу.

## Задача

Проведи целостную приёмку V01–V12 против зафиксированного облачного эталона и исправь
расхождения. Это этап доведения работающего результата, а не написания отчёта о недостатках.

## Выполни

1. Зафиксируй версию/сборку и manifest эталона 09. Подготовь сопоставимые синтетические
   данные/колонки, viewport, zoom, язык и default-настройки. Сохрани исходные личные настройки
   и восстанови их после сравнения. Cloud/reference, ModernUI before и after — разные наборы.
2. Для каждой строки V01–V12 выполни весь набор состояний из `visual-parity.md`, включая
   открытое меню, строки таблицы, выбор/hover/focus, record Summary/Details/related, Edit,
   ошибки формы, Quick Create, inventory, Settings Home и внутренние настройки, ModernUI,
   календарь и специальные экраны. Набор не сокращай до стартового списка.
3. Для сопоставимых регионов сделай пары side-by-side и overlay/diff, замеры геометрии,
   шрифтов/цветов/границ. Одинаковые имена файлов/число снимков не считаются сравнением.
   Маскируй только динамические значения по manifest; не маскируй sidebar, ширину, текстовые
   метрики, кнопки или несовпадающие поверхности. Различия модели данных проверяй структурно.
4. Исправляй P0/P1 и отклонения за согласованными допусками; повторяй затронутые пары и F.
   Скрытый старый элемент допустим только после рабочей замены всех его функций. Проверь,
   что красивые дефолты сохраняются после save/reset настроек, нового пользователя и update.
5. Облако могло измениться: сравни текущий вид с замороженным эталоном и запиши дрейф.
   Не меняй цель молча, чтобы сделать тест зелёным. Независимое визуальное суждение делай
   по измерениям/снимкам облака, не по соответствию собственной CSS-таблице.
6. Зафиксируй принятые ModernUI-baselines для последующих regression tests только после
   сравнения с облаком. Публичные тестовые снимки — лишь синтетические данные чистого стенда;
   облачные и dev-снимки остаются приватными. В GitHub Actions нужны проверки изменений
   относительно принятого результата на чистом стенде, без облачной сессии и частных данных.
   Порог шума откалибруй; необъяснённое расхождение блокирует тест, автоперезапись запрещена.
7. Проверь 1440/1920, 1024 и доступность 768/412, 200% zoom; RU/EN/DE. Для отсутствующего
   облачного аналога — отдельная оценка визуального языка и функций без ложного pixel-score.
8. Один и тот же ZIP: PACKAGE dev-стенда и оба чистых экземпляра. Пересборка после исправления
   означает новый hash и повтор затронутых сравнений. Полный F/lifecycle остаётся этапу 20,
   но все изменённые здесь функции проверь сейчас. Верни DEV, обнови отчёт и privacy.

## Готовность

- Для каждой V01–V12 есть reference ID, after, версия ZIP, измерения, результат и остаточные
  ограничения. Все обязательные сравнения выполнены, P0/P1 отсутствуют.
- Разрешённые отклонения конкретны и соответствуют `visual-parity.md`; старые отступления
  Inter/шапка v7/полноэкранная карточка/вечный sidebar не считаются согласованными.
- Есть воспроизводимый контроль регрессий принятого вида и реальные сравнения с облаком.
  Сборка, функциональные тесты и статус `full` не используются вместо этого доказательства.
