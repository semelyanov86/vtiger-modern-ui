# ModernUI 13 — Облачная карточка записи

Рабочий каталог — корень репозитория. Прочитай `PRIVATE.md` (если есть), `AGENTS.md`,
`docs/COMMON.md`, `docs/PLAN.md`, `docs/DEVELOPMENT.md`, `docs/I18N.md`, `docs/visual-parity.md`,
`docs/ui-audit.md`, design.md, architecture.md, compatibility.md и доказательства этапа 09.
Предусловие: этап 12 завершён. Если этап начат — продолжай по журналу.

## Задача

Реализуй V05–V06: открытие из списка в большой облачной карточке поверх списка, её шапку,
вкладки, сводку, детали и связанные данные. Основа — работающий прототип этапа 09.
Старое решение «полная страница v7 с новой палитрой» больше не является целевым результатом.

## Выполни

1. Повтори в облаке переход список → запись → Summary → Details → связанные данные → закрытие.
   Сверь reference IDs этапа 09: размеры окна, скругления, фон, шапка, действия, вкладки,
   прокрутка, секции и колонки. Переноси композицию доступных в Open Source функций; облачные
   Analytics/AI и другие отсутствующие функции не подменяй пустыми блоками.
2. Используй проверенный в 09 способ интеграции штатной карточки. Реальные поля, кнопки,
   handlers и права остаются CRM; Vue владеет оболочкой. Не используй iframe, копию шаблона
   ядра, скриншот, скрытую дублирующую карточку или второе API чтения/сохранения записей.
3. Шапка: значок модуля, имя, существующие ключевые поля/действия, «Изменить», контекстное меню,
   доступное закрытие/возврат. Повтори визуальную иерархию облака, сохрани PDF, подпись и
   сторонние действия из матрицы. Недостаток ширины решай доступным overflow, а не удалением.
4. Summary и Details: отдельные поверхности и область активности из реальных данных CRM;
   детали — облачные карточки секций и ритм двух колонок, контекстная навигация разделов,
   поиск по полям, если он реализуем поверх уже доступных полей. Секции/поля, скрытые правами,
   не появляются. Inline-правка, длинные значения, ссылки, изображения и пустые поля работают.
5. Связанные вкладки: списки, добавление/выбор существующей связи, действия строк, пагинация,
   комментарии, история, документы. AJAX-перезагрузка сохраняет композицию и не дублирует
   подписки. Не требуй одинаковых названий вкладок и набора полей у разных модулей.
6. Закрытие возвращает тот же список: фильтр, сортировку, страницу и прокрутку. Проверяй Back/
   Forward, повторное открытие, reload, ссылку в новой вкладке и прямой Detail URL. Прямая
   карточка имеет тот же визуальный язык и все действия; отсутствие фонового списка не ломает
   её. Политику URL/истории из 09 выполни и опиши, не навязывай SPA всей CRM.
7. Проверь типовую сущность, inventory, документы и custom module; admin/restricted user,
   запись без доступа, удалённую запись, 403/500, медленный ответ, JS failure. При несовместимом
   расширении — конкретное ограничение и доступный fallback, а не общая отмена нового вида.
8. Focus trap/возврат фокуса, Escape, вложенные dropdown/modal, прокрутка только нужной области,
   RU/EN/DE, ширины и zoom. Настоящие сохранения inline — только на синтетических данных.
9. Парные снимки V05–V06, DOM/сеть/сохранённые значения F, релевантные тесты и PACKAGE обоих
   стендов. Верни DEV, обнови карту адаптеров, журнал и privacy. Полная форма — этап 14;
   переход к ней уже должен работать без потери контекста и действий.

## Готовность

- Рабочая карточка повторяет композицию и открытие облака; старый полноэкранный v7 не остаётся
  результатом открытия поддерживаемой записи из списка.
- Прямые ссылки, связанные данные, inline, расширения и права проверены. Пустые декоративные
  блоки отсутствуют; расхождения набора возможностей перечислены отдельно от дефектов вида.
- V05–V06 и F подтверждены на обоих стендах; P0/P1 в области этапа закрыты.
