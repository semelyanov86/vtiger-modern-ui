# План разработки ModernUI

Источник истины проекта: требования, решения, статусы этапов и журнал. Документ публичный и
обезличенный; частные подробности (стенды, адреса, SHA закрытых репозиториев) — в `PRIVATE.md`.

## Требования пользователя

1. Внешний вид по образцу облачного Vtiger; исходное исследование через Chrome/Playwriter выполнено
   2026-10-29 (`RESEARCH.md`).
2. Разрешён Vue с последующей компиляцией; выбран Vue 3 + Vite.
3. Результат — работающий интерфейс, устанавливаемый отдельным модулем на Vtiger 8.4.
4. Сторонние модули и существующие рабочие сценарии должны сохраниться.
5. Нужна страница настройки темы и меню.
6. Обязательна проверка на свежеустановленной официальной Vtiger 8.4.
7. Работа идёт по промптам `docs/prompts/`, каждый этап — в новой сессии Claude Code или Codex,
   в корне этого репозитория.
8. Тема живёт в самостоятельном публичном репозитории (свой Git, не ветка CRM). Частная информация
   хранится в `PRIVATE.md` вне git (решение 2026-11-01).
9. Изменения темы сразу проверяются на dev-стенде: исходники подключаются к локальной Vtiger 8.4
   read-only (`task crm:link`), отслеживаемые файлы CRM не меняются (решение 2026-11-01).
10. Разработка начинается сразу, не дожидаясь завершения обновления CRM dev-стенда (решение 2026-11-01).
11. Полная мультиязычность самой темы: русский, английский, немецкий.
12. Frontend — TypeScript со строгой типизацией (`strict` и дополнительные флаги, `vue-tsc`,
    `typescript-eslint` strict, проверка ответов сервера во время работы); правила —
    `dependencies.md` §5 (решение 2026-11-01).

## Зафиксированные проектные ограничения

- Самостоятельный extension ZIP, без патчей ядра, замены глобальных библиотек и зависимости от
  конкретной установки.
- Внутри ZIP готовая production-сборка; исходники и инструменты сборки — отдельно.
- Основной интерфейс v7 остаётся основой совместимости. Vue владеет своими контейнерами.
- Настройки серверные, права Vtiger обязательны, стандартный вид и восстановление доступны.
- Рабочее имя ModernUI; при конфликте имени этап 01 переименовывает последовательно (включая
  `dev/crm-mounts.txt` и `MU_MODULE`) до появления устанавливаемого пакета.
- DEV: подключение `src/` к dev-стенду bind mounts read-only + PHP-заглушки языков; регистрация в
  базе стенда — штатным lifecycle. PACKAGE: чистый стенд 8.4 в Docker и dev-стенд без подключения,
  только конечный ZIP. Контракт — `DEVELOPMENT.md`.
- Прежняя схема (отдельный приватный runtime CRM с переключением адреса стенда, ожидание завершения
  обновления CRM) отменена 2026-11-01.
- `I18N.md` задаёт RU/EN/DE, fallback, локализацию меню и проверки на обоих типах стендов.
- Общие правила, в том числе миграции собственных настроек и публичность: `COMMON.md`.
- Выпуск не означает разрешение на публикацию, коммит, пуш или установку на рабочие серверы.
- Архитектура (этап 01, `architecture.md`): extension-модуль; слой skin — CSS через `HEADERCSS` в
  `<head>`, слой shell — Vue-острова через классический загрузчик `HEADERSCRIPT`; обе ссылки
  `tabid=0` с обработчиком ссылки, который решает per-user/per-screen; ссылки и миграции — в
  `vtlib_handler`, не в manifest; шапка v7 сохраняется и переоформляется, мега-меню темы заменяет
  только меню приложений; карточка и форма остаются полными страницами v7; безопасный режим
  `modernui=off`; библиотека компонентов — Reka UI + собственный набор `Mu*` (`dependencies.md`).

## Документы, которые появятся по этапам

- architecture.md — точки расширения, границы DOM, структура пакета, решения.
- design.md — визуальные правила и критерии приёмки экранов.

выполнением этапа.

## Итоговые условия готовности

- Один и тот же релизный ZIP установлен штатным менеджером на свежую официальную 8.4 и на dev-стенд
  в PACKAGE без подключения исходников; финальный пакет проверен повторно на новой чистой базе.
- Новый вид охватывает рабочие списки, карточки, формы, навигацию и основные служебные экраны.
  Не осталось неработающих кнопок, декоративных настроек и заглушек.
- Настройки сохраняются, действуют после перезагрузки, корректно разделяются по пользователям/ролям;
  меню не расширяет права и не теряет новые модули.
- Права, сохранение, динамические поля, товарные позиции, расчёты, связанные списки, документы и
  сторонние действия проверены по матрице; необъяснённых регрессий нет.
- Install → enable → disable → enable → update → uninstall → reinstall проверены. Настройки
  сохраняются при обновлении, ядро не изменяется, чужие данные не удаляются.
- Сбой загрузки frontend и аварийный переход на стандартный вид проверены.
- ZIP не требует Node/Phinx/CLI на сервере и не содержит данных клиентов/секретов/чужого
  коммерческого кода. Есть исходники, lockfile, инструкция и воспроизводимая сборка.
- Правки PHP, Smarty, Vue/CSS и переводов видны на dev-стенде без ручного копирования и повторного ZIP.
- Интерфейс и настройки темы полностью проверены на RU/EN/DE, включая fallback, личный язык и
  локализованные подписи меню; нет ключей/пустых переводов в UI.
- Отслеживаемые файлы, конфиги и git CRM dev-стенда не менялись из-за разработки темы.
- В публикуемых файлах и истории git нет частной информации (`task privacy`).

- Подключение к стенду: `dev/crm-link.sh` (`task crm:link|unlink|status|smoke`), карта
  `dev/crm-mounts.txt`, статус регистрации `dev/crm-info.php`, `task lint`.
- Проверено на dev-стенде (Vtiger 8.4.0, PHP 8.5 FPM) пробным модулем, временные файлы удалены:
  - симлинки исключены: `checkFileAccessForInclusion()` сравнивает `realpath()` с корнем CRM;
  - bind mount: PHP-FPM видит файлы, `realpath()` внутри корня, правка PHP видна после перезагрузки,
    сохранение через rename видно сразу;
  - в namespace PHP-FPM (`ProtectSystem=full`) bind mount приходит writable; после `nsenter … remount,ro`
    запись из PHP — «Read-only file system»;
  - языковые заглушки: `Vtiger_Language_Handler` отдал строки из файлов репозитория (RU и DE);
  - `--force` переносит ZIP-копию в `.local/crm-replaced/`, повторные link/unlink идемпотентны;
  - `git status` CRM всё время без изменений, исключения — в её `.git/info/exclude`.
- Репозиторий публичный: частное вынесено в `PRIVATE.md` (в `.gitignore`) и `.env`; `dev/crm-link.sh`
  без умолчаний конкретной машины; `task privacy` проверяет публикуемые файлы по шаблонам из `PRIVATE.md`.

### 2026-11-01 — Архитектура и спецификация (этап 01)

- Окружение: репозиторий — собственный `.git`, в истории и рабочем дереве нет кода CRM, `.env`,
  vendor, дампов; remote `origin` настроен мейнтейнером (AGENTS.md обновлён). dev-стенд: Vtiger 8.4.0,
  HTTP 200, `task crm:smoke` зелёный, `git status` CRM чистый, пути ModernUI не подключены (исходников

- Имя `ModernUI` свободно: нет в `vtiger_tab`, `vtiger_links`, `vtiger_settings_field`, таблицах и
  каталогах стенда, в теге `8.4.0`, в публичных сведениях о Vtiger Marketplace. Переименование не нужно.
- Точки расширения проверены по тегу `8.4.0` и коду стенда (цепочка `getHeaderScripts/getHeaderCss`,
  `Vtiger_Link::getAllByType` с обработчиком, фильтр прав ссылок, `PackageImport/PackageUpdate/Unzip`,
  lifecycle-события и их порядок, `vtlib_addSettingsLink`, языки, меню, PJAX, csrf-magic). Найдено:
  в 8.4.0 `import_CustomLinks` теряет обработчик ссылки; ресурсы выключенного модуля админу
  выводятся; при update файлы распаковываются до `preupdate`; `fetch` не получает CSRF-токен
  автоматически; установщик создаёт базу `utf8`. Решения — `architecture.md` §1.
- Прототип загрузчика (Vite 8.3.5, Vue 3.5.44, headless Chromium): `text/javascript` →
  `manifest.json` → `<script type="module">` работает в корне и подкаталоге `/vtigercrm/`, с хвостом
  `?v=8.4.0`; сбои manifest/entry/chunk оставляют v7.
- Облачный образец измерен (Playwriter, вход пользователя, только чтение, модуль Leads): токены,
  мега-меню вместо боковой панели, полоса избранного, плотность; отступления ради AA и совместимости
  отмечены в `design.md`. Снимки — в приватном каталоге.
- Библиотека компонентов выбрана экспериментом (4 кандидата, реальный CSS v7, 29 точек замера,
  клавиатура, размер, лицензии): Reka UI 2.11.0 + свой набор `Mu*`; PrimeVue 5 — коммерческая
  лицензия, PrimeVue 4 — rem при `html{font-size:10px}`; Naive — слабая доступность; Element Plus —
  план Б. `@layer` и `outline`-фокус непригодны на странице v7 (проверено).
- Реестр DOM/JS-зависимостей расширений стенда (только чтение): публичная выжимка и каталог событий
  ядра — `compatibility.md`, частное — `PRIVATE.md`.
- Решение мейнтейнера: TypeScript в строгом режиме (требование 12).
- `dev/crm-mounts.txt` совпадает со спроектированной структурой — без изменений. Обновлены
  `DEVELOPMENT.md`, `README.md`, `AGENTS.md`.
