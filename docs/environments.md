# Стенды ModernUI

Этап 01, 2026-11-01: проект стендов. DEV и подключение описаны в `DEVELOPMENT.md`; здесь — что
развёртывает этап 03 (чистый стенд) и как выполняется PACKAGE-прогон на dev-стенде. Конкретные
адреса, пути и учётные записи dev-стенда — только в `PRIVATE.md`/`.env`.

## 1. Виды стендов

| Стенд | Назначение | Источник CRM | Исходники темы | База |
|---|---|---|---|---|
| dev-стенд, DEV | ежедневная разработка | локальная Vtiger 8.4 из `.env` | подключены read-only (`task crm:link`) | своя база стенда, регистрация — `task crm:install/update` |
| dev-стенд, PACKAGE | установка ZIP на реальную CRM | то же | **отключены** (`task crm:unlink`) | та же |
| чистый стенд | переносимость: свежая официальная 8.4.0 | тег `8.4.0` официального репозитория | нет, только ZIP через менеджер модулей | новая, синтетические данные |

Чистый стенд не получает патчи, миграции и дамп dev-стенда.

## 2. Чистый стенд (этап 03)

### 2.1. Состав

Docker-проект в `dev/clean/` (Compose, закреплённые digest образов, записываются в этот документ при
создании):

| Сервис | Образ | Настройки |
|---|---|---|
| `db` | `mysql:8.4` (вариант `mysql:8.0`) | `--sql-mode=NO_ENGINE_SUBSTITUTION` (установщик и ядро Vtiger требуют без `STRICT_TRANS_TABLES`, `ONLY_FULL_GROUP_BY`, `NO_ZERO_*` — `modules/Install/models/Utils.php:320`), том `clean-db` |
| `web81` | сборка от `php:8.1-apache` | расширения `mysqli`, `imap`, `curl`, `gd`, `zip`, `intl`, `mbstring`, `xml`, `opcache`; `display_errors=Off`, `error_reporting=E_ALL`, журнал PHP в stdout; `max_execution_time=0` для установщика |
| `web85` (по возможности) | сборка от `php:8.5-apache` | то же; `imap` в PHP ≥ 8.4 вынесен в PECL — если `pecl install imap` не собирается под 8.5, вариант помечается «не реализован» с причиной |
| `mail` | `axllent/mailpit` | SMTP для CRM, веб-интерфейс только на `127.0.0.1` |

Код CRM: `git archive` тега `8.4.0` официального репозитория (коммит
`0bb3774e7df04c40bc2cc81b1f910a6b1ae77be2`, `vendor/` входит в тег) или официальный архив релиза
8.4.0 с записанной SHA-256 — выбор и контрольная сумма фиксируются здесь на этапе 03. Код
распаковывается в том `clean-crm` (не в репозиторий темы), права на запись — как требует установщик
(`config.inc.php`, `tabdata.php`, `parent_tabdata.php`, `cache/`, `storage/`, `user_privileges/`,
`modules/`, `cron/modules/`, `test/`, `logs/`, `languages/`, `layouts/`).

Адреса (свои порты, не адрес dev-стенда; значения — в `.env`: `MU_CLEAN_PORT`, `MU_CLEAN_SUBDIR_PORT`):

- `http://127.0.0.1:${MU_CLEAN_PORT}/` — CRM в корне;
- `http://127.0.0.1:${MU_CLEAN_SUBDIR_PORT}/vtigercrm/` — та же сборка в подкаталоге (отдельная база
  или отдельный экземпляр — решается на этапе 03, требование — проверка базового URL);
- `site_URL` совпадает с фактическим адресом (иначе ядро перенаправляет на `site_URL`).

### 2.2. Установка и данные

1. `task clean:up` — сборка образов, запуск, распаковка CRM в том.
2. `task clean:install` — установщик Vtiger проходится автоматически (Playwright по шагам
   `module=Install&view=Index&mode=Step1…Step7`, язык en_us, валюта, администратор с паролем из
   `.local/clean/admin.env`, генерируется при первом запуске, в git не попадает). Установщик создаёт
   базу `utf8`/`utf8_general_ci` — это и есть проверяемая конфигурация чистой 8.4.0.
3. `task clean:seed` — синтетические данные через webservice REST (`webservice.php`, вход по
   access key администратора): организации, контакты, обращения, сделки, товары, заказ с товарными
   строками, документы, задачи; второй пользователь с ограниченной ролью/профилем и третий с
   полным просмотром — для проверок прав и пилота. Генератор — `tests/fixtures/`; данные заведомо
   вымышленные (RU/EN/DE имена с умляутами и кириллицей).
4. `task clean:snapshot` / `task clean:restore` — снимок тома базы и CRM до установки ModernUI, чтобы
   повторять install/update/uninstall с одного состояния.
5. `task clean:reset` — удалить тома (новая чистая база), `task clean:down` — остановить.

Языки: штатная 8.4.0 содержит только `en_us`. Основная проверка — тексты темы RU/EN/DE через личный
выбор языка темы. Дополнительный вариант — тот же стенд с официальным языковым пакетом de_de/ru_ru
из Marketplace/архива, если он доступен для 8.4 (не обязательно, отмечается отдельно).

### 2.3. Установка ModernUI на чистый стенд

Только штатный путь: `task clean:import-zip` открывает «Settings → Module Manager → Import Module»
под администратором и загружает `dist/ModernUI-X.Y.Z.zip` через интерфейс (Playwright), принимает
лицензию, ждёт результата. Обновление — тот же путь для ZIP новой версии («Update»). Ручное
копирование файлов и SQL после импорта запрещены. `task clean:status` показывает регистрацию
(`dev/crm-info.php` в контейнере), ссылки, пункт настроек, таблицы.

### 2.4. Проверки чистого стенда (минимум этапа 03)

- импорт ZIP, тема выключена у всех; включение для администратора; страница настроек;
- пользователь с ограниченным профилем получает тему через пилот без пересоздания привилегий
  (`architecture.md` Q2);
- disable/enable в менеджере модулей, update ZIP, удаление (`console.php --remove`), повторная установка;
- RU/EN/DE текстов темы при `en_us` у CRM; fallback;
- корень и подкаталог; PHP 8.1 и (если реализован) 8.5; журнал PHP без предупреждений/deprecated
  от файлов ModernUI;
- отсутствие dev-URL и ссылок на каталог репозитория в сетевых запросах.

## 3. PACKAGE-прогон на dev-стенде

| Шаг | Команда / действие | Контроль |
|---|---|---|
| 1 | `task package` | ZIP и `.sha256` в `dist/`, проверки состава пройдены |
| 2 | `git -C "$CRM_ROOT" status --porcelain > .local/package/git-before.txt` | исходное состояние git CRM |
| 3 | `task crm:unlink` | `task crm:status`: все пути «not linked», заглушек нет |
| 4 | Менеджер модулей → Импорт (или Update, если модуль зарегистрирован) → тот же ZIP | `task crm:status`: пути `INSTALLED` (реальные файлы), версия модуля = версии ZIP |
| 5 | Сценарии `verification.md` (DEV-специфичные отмечены) | в сетевых запросах нет адресов dev server и путей репозитория |
| 6 | `git -C "$CRM_ROOT" status --porcelain` | совпадает с шагом 2 (пути ModernUI исключены блоком `.git/info/exclude`) |
| 7 | `task crm:link -- --force` | установленная копия перенесена в `.local/crm-replaced/<время>/`, подключение восстановлено |
| 8 | `task crm:update`, если версия схемы в рабочей копии новее | регистрация соответствует исходникам |

Никогда не импортировать ZIP поверх подключённых исходников: read-only mount сорвёт распаковку на
середине.

## 4. DEV на dev-стенде (кратко)

`task crm:link` → `task build` / `task dev` → правка в `src/`/`frontend/` → перезагрузка страницы.
Регистрация и миграции — `task crm:install` (первый раз, после пересоздания базы стенда) и
`task crm:update` (новая версия схемы, ссылки). Подробно — `DEVELOPMENT.md`.
