# Разработка и проверка: dev-стенд и чистая Vtiger 8.4

Тема разрабатывается в этом репозитории и проверяется сразу на **dev-стенде** — локальной установке
Vtiger 8.4, заданной в `.env` (`CRM_ROOT`, `CRM_URL`). У мейнтейнера это копия реальной CRM с большим
числом сторонних модулей; конкретный стенд, вход, логи и запреты — в `PRIVATE.md`.

Переносимость установки доказывает только ZIP, импортированный штатным менеджером модулей (режим
PACKAGE): на **чистом стенде** (свежая официальная 8.4) и на dev-стенде без подключённых исходников.

## Кто что может менять

| Часть | Разрешённая запись из проекта темы |
|---|---|
| Этот репозиторий | код, документация, тесты, сборка |
| Файлы dev-стенда (`$CRM_ROOT`) | только пути ModernUI из `dev/crm-mounts.txt` (`task crm:link` или импорт ZIP) и `test/templates_c/v7` |
| База dev-стенда | регистрация ModernUI штатным lifecycle vtlib, собственные таблицы модуля, синтетические записи сценариев |
| Git CRM dev-стенда | только блок исключений ModernUI в её `.git/info/exclude` |
| Чистый стенд | полностью свой (Docker-проект темы, этап 03) |
| Эталон ядра (официальные исходники, тег `8.4.0`) | ничего, только чтение |
| Приватный каталог данных (`PRIVATE.md`) | скриншоты и выгрузки с данными клиентов |

Отслеживаемые git файлы CRM dev-стенда, её `.env`, `config*.php`, миграции и ветки не меняются.
`task crm:status` показывает число изменённых путей в `git status` CRM — тема его не меняет.

## Как устроено подключение (DEV)

`task crm:link` (`dev/crm-link.sh`) подключает исходники к стенду по карте `dev/crm-mounts.txt`.
Каждая строка карты — один и тот же относительный путь в `src/` и в корне CRM. Поэтому `src/`
повторяет раскладку, которую создаёт импорт ZIP:

| В `src/` и в CRM | Способ | В ZIP (vtlib PackageImport 8.4.0) |
|---|---|---|
| `modules/ModernUI/` | bind mount, read-only | `modules/ModernUI/` |
| `modules/Settings/ModernUI/` | bind mount, read-only | `settings/{actions,views,models,…}/` |
| `layouts/v7/modules/ModernUI/` | bind mount, read-only | `layouts/v7/modules/ModernUI/` |
| `layouts/v7/modules/Settings/ModernUI/` | bind mount, read-only | `layouts/v7/modules/Settings/ModernUI/` |
| `languages/<lang>/ModernUI.php` | PHP-заглушка с `require` | `languages/<lang>/ModernUI.php` |
| `languages/<lang>/Settings/ModernUI.php` | PHP-заглушка с `require` | `languages/<lang>/Settings/ModernUI.php` |

`manifest.xml` и прочие файлы корня пакета в CRM не подключаются. Этап 01 может изменить структуру;
тогда он же правит карту и сборку ZIP, чтобы пути совпадали.

Почему так (проверено пробным модулем на dev-стенде, Vtiger 8.4 + PHP-FPM под systemd):

- **Симлинки не годятся.** `checkFileAccessForInclusion()` (`vtlib/Vtiger/Utils.php`,
  `includes/Loader.php`, `includes/runtime/LanguageHandler.php`) сравнивает `realpath()`
  подключаемого файла с корнем CRM и завершает запрос «Attempt to access restricted file».
  У bind mount `realpath()` остаётся внутри корня.
- **PHP-FPM живёт в своём mount namespace** (systemd `ProtectSystem=full`). Новый bind mount приходит
  туда доступным для записи, поэтому скрипт перемонтирует его read-only в namespace каждого запущенного
  `php*-fpm`. Итог: PHP читает правки сразу, но не может записать в исходники темы
  (`file_put_contents` → «Read-only file system»).
- **Одиночный файл не монтируется.** Bind mount файла «залипает» на старом inode, когда редактор
  сохраняет через rename. Поэтому для языковых файлов в CRM пишется заглушка `require '<путь в src>'`
  с меткой «ModernUI dev link»; штатный `Vtiger_Language_Handler` проходит проверку пути по заглушке
  и получает `$languageStrings` реального файла.
- Пути карты исключены из git CRM блоком в её `.git/info/exclude` (локально, не коммитится).
- Файлы, которые мешают подключению (копия, установленная из ZIP), без `--force` не трогаются;
  с `--force` переносятся в `.local/crm-replaced/<время>/`, не удаляются.
- При изменении подключения очищается `test/templates_c/v7` (скомпилированные шаблоны Smarty).
- Состояние — `.local/crm-link.state`. Повторный `crm:link`/`crm:unlink` безопасен.
- Нужен `sudo` без пароля (mount, umount, nsenter); `crm:link` отказывается работать с Vtiger не 8.4.

## Команды

| Команда | Что делает |
|---|---|
| `task crm:link` | подключить `src/` к стенду; `task crm:link -- --force` — убрать мешающую ZIP-копию в `.local/` |
| `task crm:unlink` | отключить (размонтировать, удалить заглушки); база стенда и регистрация модуля остаются |
| `task crm:status` | версия и git HEAD стенда, состояние каждого пути (ro в каждом namespace PHP-FPM), регистрация модуля в БД |
| `task crm:smoke` | smoke-тест самого стенда, если у CRM есть `task smoke` |
| `task lint` | `php -l` под PHP 8.5 и 8.4 |
| `task privacy` | частная информация (шаблоны из `PRIVATE.md`) в публикуемых файлах |

Этап 02 добавляет: сборку frontend, watch, сборку ZIP, `task crm:install`, `task crm:update`,
`task crm:uninstall`, нижнюю границу PHP 8.1 в `lint`, тесты (спроектировано в `architecture.md` §13).
Этап 03 — команды чистого стенда 8.4 (`environments.md` §2).
Новые команды описываются здесь, в `README.md` и `AGENTS.md`.

Стенд выбирается в `.env` (`.env.example`): `CRM_ROOT`, `CRM_URL`, `CRM_PHP`, `CRM_FPM_LOG`,
учётная запись для браузерных тестов `CRM_ADMIN_USER` и `CRM_ADMIN_PASS` или `CRM_ADMIN_PASS_FILE`.
Одновременно подключение работает только к одному стенду; для смены — `task crm:unlink`, правка
`.env`, `task crm:link`.

## Правка → результат на dev-стенде

| Что правите | Когда видно |
|---|---|
| PHP модуля и настроек | после перезагрузки страницы; OPcache проверяет mtime с периодом `opcache.revalidate_freq` (обычно 2 с) |
| Smarty `.tpl` | после перезагрузки (Smarty перекомпилирует по mtime) |
| PHP-словари `languages/*` | после перезагрузки (заглушка подключает файл заново) |
| Vue, CSS, словари frontend | после пересборки watcher'ом (этап 02) и перезагрузки |
| `manifest.xml`, ссылки, таблицы, версия схемы настроек | не через подключение: `task crm:update` (штатный lifecycle) |
| Новый путь карты (например, новый язык) | повторный `task crm:link` |

Требования к сборке frontend (этап 02): результат пишется внутрь подключённого каталога
(`src/layouts/v7/modules/ModernUI/resources/dist/`, исключён из git; устройство — `architecture.md` §5), без ссылок на dev server в
production-сборке. Пересборка атомарна: сначала новые chunks, последним — manifest; смесь старого
manifest и удалённых chunks недопустима. Ошибка компиляции не оставляет пустой или битый результат.
HMR — только как улучшение, только на localhost, с проверенной совместимостью с legacy-загрузчиком;
без него достаточно `vite build --watch`. Режим разработки определяется окружением сборки, а не
URL-параметром обычного пользователя.

## Регистрация модуля в базе стенда

Подключение даёт только файлы. Чтобы Vtiger знал модуль (`vtiger_tab`, ссылки HEADERSCRIPT/HEADERCSS,
пункт настроек, собственные таблицы), нужен штатный lifecycle. Этап 02 реализует:

- `task crm:install`: собрать ZIP → `crm:unlink` → импорт тем же кодом, что и менеджер модулей
  (`Vtiger_Package::import`, CLI-обвязка в `dev/`) → перенести распакованные файлы ModernUI
  в `.local/crm-replaced/` → `crm:link`.
- `task crm:update`: то же через штатное обновление пакета; миграции собственных настроек выполняет
  lifecycle-обработчик модуля.
- Удаление — штатно (менеджер модулей или vtlib), по политике модуля из `settings.md`.

Ручной SQL вместо lifecycle запрещён. `task crm:status` показывает регистрацию: tabid, включён ли
модуль, версию, ссылки, пункты настроек, собственные таблицы. Перед первой регистрацией зафиксируй
исходное состояние `task crm:status` (частные подробности — в `PRIVATE.md`).

Типовые ситуации:

- после перезагрузки компьютера bind mounts пропадают → `task crm:link`;
- после пересоздания базы стенда регистрация пропадает → `task crm:install`;
- `crm:unlink` при включённом модуле предупреждает: модуль зарегистрирован, а файлов нет. Перед
  чужими работами на стенде отключите модуль в менеджере модулей или верните подключение.

## PACKAGE: проверка установочного ZIP

**Чистый стенд** (этап 03). Docker-проект внутри репозитория с закреплёнными образами: официальный
релиз 8.4.0 (или тег `8.4.0` официального репозитория) с записанной контрольной суммой/SHA, новая
пустая база, штатный установщик Vtiger, нижняя граница PHP 8.1 (и вариант на 8.5, если реализуемо),
свой адрес (не адрес dev-стенда), своя почтовая ловушка или отключённая почта. Без подключения `src/`,
без watcher и Vite. Штатная 8.4.0 содержит только `en_us`: немецкий и русский интерфейс ядра там не
появится, тексты самой темы — обязаны.

**dev-стенд без подключения:**

1. `task crm:unlink` (импорт поверх read-only подключения провалится на полпути — не делайте так);
2. «Настройки → Менеджер модулей → Импорт» под администратором, тот же ZIP;
3. проверки сценариев;
4. возврат в DEV: `task crm:link -- --force` (установленная копия уйдёт в `.local/crm-replaced/`),
   при новой версии схемы — `task crm:update`.

Фраза «установи ZIP на оба стенда» в этапах означает эти два PACKAGE-прогона. После PACKAGE тема
не должна «работать» за счёт файлов из репозитория: проверяй отсутствие заглушек и подключений
(`task crm:status`), отсутствие dev URL в сетевых запросах.

## Данные dev-стенда

- База может быть копией рабочей CRM с персональными данными. Перед сценариями записи убедись,
  что исходящие интеграции отключены и почта уходит в ловушку (как именно — `PRIVATE.md`).
  Подстановка SMTP сама по себе не отключает телефонию, учётные системы, мессенджеры и webhooks.
- Только синтетические записи; удаляй только свои. Скриншоты и выгрузки с данными клиентов —
  в приватный каталог из `PRIVATE.md`, не в git.
- dev-стенд может использоваться и для других работ: команды CRM, пересоздающие базу, останавливающие
  службы или запускающие её миграции, а также правка её кода, `.env` и конфигов — только по просьбе
  пользователя.

## Доказательство невмешательства

- До и после подключения, правок, сценария записи и отключения: `git -C "$CRM_ROOT" status --porcelain`
  не меняется из-за темы (чужие параллельные изменения фиксируй и не откатывай).
- `task crm:status`: все подключённые каталоги `ro` в каждом namespace PHP-FPM.
- В базе стенда после удаления модуля не остаётся ссылок, пунктов настроек и таблиц ModernUI (по
  политике удаления); бизнес-данные и права CRM не изменены.
- Сборка и watcher пишут только в каталог темы.

Первичные источники: [Vite backend integration](https://vite.dev/guide/backend-integration.html),
[Vite build](https://vite.dev/guide/build.html), [mount(8) bind mounts](https://man7.org/linux/man-pages/man8/mount.8.html),
[systemd ProtectSystem](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html#ProtectSystem=).
