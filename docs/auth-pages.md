# Страницы авторизации

Дополнение к этапу 16, по запросу пользователя от 2026-11-10. Отдельная кнопка администратора
«Применить страницы входа» в «Настройки → ModernUI → Обслуживание» устанавливает оформление
входа, восстановления и смены пароля по ссылке. Действует для всех посетителей, независимо от
пилота и личных настроек. Это согласованное исключение из запрета изменений ядра; обычный импорт
или обновление ZIP страницы входа не переключает.

## Настройки и поведение

- Логотип: отдельная загрузка ModernUI → логотип организации → стандартный Vtiger, если нет файла.
  Загрузка уже доступна в «Оформлении»: PNG/JPEG/GIF, до 512 КБ; сервер проверяет, перекодирует
  и уменьшает до 600×200, достаточно для изображения высотой 40 CSS px. Логотип документов не меняется.
- «Показывать надпись» и текст RU/EN/DE в «Оформлении» управляют общей надписью над формой и
  под логотипом шапки. По умолчанию выключена. Текст публичный, HTML запрещён. Известная старая
  надпись непосредственно в ссылке логотипа скрывается только при работающей оболочке ModernUI.
- Язык: выбор посетителя (сохраняется в сессии, включая ошибки форм) → общий язык темы → язык CRM → английский. Шрифты и собственный
  рисованный SVG-фон находятся в ZIP, внешних ресурсов нет. Форма работает без JavaScript.
- Вход и восстановление используют штатные действия Vtiger: имя пользователя/пароль,
  имя пользователя/почта, затем штатная ссылка из письма. Подтверждение пароля проверяется в
  браузере и штатным сервером. Неподключённых способов социального входа и регистрации нет.
- Размеры: логотип 40 px, вход 300 px, восстановление 510 px, поля и кнопки 38 px; Poppins 16 px,
  кириллица Arial/Arimo. Дополнительное поле почты обусловлено штатным восстановлением Open Source.

## Установка и возврат

`AuthInstaller` меняет только `layouts/v7/modules/Users/Login.tpl` и
`layouts/v7/modules/Users/ForgotPassword.tpl`. Обёртка загружает собственные шаблоны ModernUI,
сохраняя исходное содержимое как fallback. При безопасном режиме, выключенном/отсутствующем
модуле, недоступных настройках или сборке показывается исходная страница.

Оригиналы, права и SHA-256 записываются до изменения в `test/modernui-auth/state.php`
(каталог 0700, файл 0600, PHP `exit` перед содержимым). Блокировка сериализует нажатия;
каждый файл заменяется атомарным rename. Исходники чужой CRM не входят в ZIP.
Повторное применение ничего не меняет, частичную установку можно завершить или отменить.

«Вернуть исходные страницы» восстанавливает файлы побайтно и удаляет резервную копию.
Удаление модуля также сначала возвращает шаблоны. Отключение модуля использует fallback.
Если файлы изменены другим расширением/администратором или резервная копия повреждена,
операция останавливается без перезаписи. Сохранить изменённые шаблоны и копию, согласовать
расхождения с администратором; не удалять копию ради снятия блокировки. Перед обновлением
ядра вернуть исходные страницы, после обновления применить оформление заново.

Установке нужны права PHP на запись в каталоги этих двух шаблонов и `test/`. Других каталогов
ядра эта функция не меняет. Кнопки — POST с CSRF, доступны только администратору; пути запроса
не принимаются. Порядок DEV/PACKAGE прежний: импорт ZIP после unlink, проверка, возврат link.

## Проверка

`task test:auth-pages` (`MU_E2E_TARGET=dev|c81|c85`) сохраняет и восстанавливает общие настройки
и состояние шаблонов. Проверяет настоящий вход, неверный пароль, восстановление без JS,
загрузку/смену логотипа, условную надпись, RU/EN/DE, пять ширин, безопасный режим,
установку/возврат, CSRF и права. `MU_AUTH_SHOTS_DIR` включает снимки (на dev — приватный каталог).
`MU_AUTH_MAIL_URL` включает только на чистом стенде полный путь через его почтовую ловушку:
отправка письма, ссылка, подтверждение пароля и свежий вход; исходный пароль синтетического
пользователя сохраняется. Письмо этого сценария удаляется из ловушки.
