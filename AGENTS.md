# AGENTS.md — ModernUI

Канонический документ для ИИ-агентов (Claude Code, Codex, Cursor и др.). `CLAUDE.md` подключает
этот файл — правьте только `AGENTS.md`, чтобы не было двух расходящихся копий.

## 0. Публичный репозиторий и PRIVATE.md

Репозиторий публичный. Если в корне есть **`PRIVATE.md`** (в `.gitignore`), прочитай его первым:
там конкретные стенды, пути, доступы, запреты, обязательная матрица dev-стенда и частный журнал.
Его правила дополняют этот файл и имеют приоритет в вопросах окружения.

В отслеживаемые файлы (README, AGENTS.md, `docs/`, код, тесты, конфиги) **не писать**: названия
компании и заказчиков, домены, хосты, IP, локальные пути машины, имена пользователей, имена баз,
контейнеров и портов, SHA и пути закрытых репозиториев, адрес облачного эталона, названия
собственных модулей и полей конкретной CRM, данные и скриншоты. Такие подробности — только в
`PRIVATE.md`, `.env`, `USAGE.md` или `.local/`. Нейтральные термины: «dev-стенд», «чистый стенд»,
`$CRM_ROOT`, `$CRM_URL`. Перед завершением сессии и перед коммитом — `task privacy`.

## 1. Что это за проект

**ModernUI** — самостоятельный устанавливаемый extension-модуль для **Vtiger CRM Open Source 8.4**:
новый интерфейс по образцу облачного Vtiger (Vue 3 + Vite), страница «Настройки → ModernUI»
(оформление, меню, личные предпочтения), тексты темы на русском, английском и немецком.
Результат — ZIP, который ставится штатным менеджером модулей на любую чистую 8.4.

Конкретная CRM, на которой ведётся разработка, — только тестовый стенд. Модуль не должен от неё зависеть.

## 2. Начало и конец сессии

1. Прочитать `PRIVATE.md` (если есть), `docs/PLAN.md` (требования, решения, статусы, журнал) и
   `docs/COMMON.md`. `docs/DEVELOPMENT.md` и `docs/I18N.md` обязательны для этапов с кодом и проверками.
2. Задание этапа — `docs/prompts/NN-*.md`; выполнять только его. Если этап уже начат — продолжать
   по журналу, не начинать заново.
3. В конце — обезличенная запись в «Журнал» `docs/PLAN.md` и статус этапа в таблице; частные
   подробности — в частный журнал `PRIVATE.md`. Затем `task privacy`.
   Порядок запуска промптов для пользователя — `USAGE.md` (локальный файл, в `.gitignore`).
4. Последняя строка ответа на этапе: «ModernUI NN: ЗАВЕРШЁН» или
   «ModernUI NN: НЕ ЗАВЕРШЁН — запустите этот же промпт снова» (критерии — `docs/COMMON.md`).

## 4. Цикл разработки на dev-стенде

```bash
task crm:link      # src/ → dev-стенд: каталоги bind mount read-only, языки — PHP-заглушки с require
task crm:status    # стенд, версия, git HEAD CRM, состояние путей (ro в namespace PHP-FPM), регистрация в БД
task crm:unlink    # отключить; база стенда и регистрация модуля остаются
task crm:smoke     # smoke-тест стенда, если у CRM есть `task smoke`
task lint          # php -l под 8.5 и 8.4
task privacy       # нет ли частной информации в публикуемых файлах
```

- Правишь **только** в `src/` этого репозитория → перезагружаешь страницу dev-стенда. PHP виден
  через ≤ 2 с (OPcache), Smarty — сразу, языки — сразу. Vue/CSS — после пересборки watcher'ом.
- Файлы ModernUI внутри `$CRM_ROOT` — подключённые read-only каталоги и заглушки, не копии.
  Не редактируй их там и не копируй в CRM вручную.
- Симлинки не работают: Vtiger сверяет `realpath()` подключаемых файлов с корнем CRM.
- Пути ModernUI исключены из git CRM в её `.git/info/exclude` — в `git status` CRM их нет.
- Регистрация модуля в базе (vtiger_tab, ссылки, пункт настроек, свои таблицы) — только штатным
  lifecycle: `task crm:install` / `task crm:update` (этап 02), импорт ZIP, менеджер модулей.
  Ручной SQL запрещён.
- После перезагрузки компьютера — `task crm:link`. После пересоздания базы стенда — `task crm:install`.
- Проверка ZIP (PACKAGE) на dev-стенде: `task crm:unlink` → импорт ZIP в менеджере модулей →
  проверки → `task crm:link -- --force`. Никогда не импортируй ZIP поверх подключённых исходников.
- Подробно — `docs/DEVELOPMENT.md`; конкретный стенд, вход, логи, чтение базы — `PRIVATE.md`.

База dev-стенда может быть копией рабочей CRM с персональными данными: только синтетические записи,
удалять только свои, перед сценариями записи убедиться, что интеграции отключены. Команды CRM,
которые пересоздают базу, останавливают службы или запускают её миграции, — только по просьбе пользователя.

## 5. Правила кода

- Целевая платформа модуля: Vtiger 8.4, PHP **8.1–8.5**, MySQL 8.x. Без предупреждений и deprecated.
  Синтаксис — `task lint`.
- Никаких патчей ядра и чужих модулей, копий файлов ядра в пакете, замены глобальных jQuery/Bootstrap/
  Select2, второго глобального Vue. CSS — только под признаком активной темы и в своих компонентах.
- Vue монтируется только в собственные контейнеры; DOM, которым управляет jQuery, не пересоздаётся.
- Пакет не зависит от конкретной установки: никаких tabid/roleid/userid, `cf_*`, доменов, абсолютных путей.
- Все тексты темы — сразу на RU/EN/DE (`docs/I18N.md`), английский fallback.
- PHP и Smarty — табы, как в ядре Vtiger; комментарии и имена — по-английски, общение — по-русски.
- Собственные настройки — версионированная схема и идемпотентные миграции внутри пакета.

## 6. Git

- Ветка `main`, remote пока нет — не создавать и не угадывать.
- **Коммитить и пушить только по просьбе пользователя.** Сообщения — Conventional Commits.
  Перед коммитом — `task privacy`.
- `README.md` — на английском, инструкция для разработчика; меняются команды или окружение — обнови
  его вместе с `docs/DEVELOPMENT.md`. Работа с промптами — только в локальном `USAGE.md`.
- В git не попадают: `.env`, `PRIVATE.md`, `USAGE.md`, `.local/`, секреты, дампы, данные и скриншоты
  клиентов, `node_modules/`, `dist/`, код CRM стенда и чужие коммерческие модули.

## 7. Чего не делать

- Не трогать серверы, перечисленные в `PRIVATE.md` как запретные (прод, staging и т. п.).
- Не коммитить, не переключать ветки, не делать reset/stash/merge в репозитории CRM dev-стенда;
  не править его отслеживаемые файлы и не создавать там миграций для темы.
- Не подключать модуль к установке, где Vtiger не 8.4.
- Не включать коммерческий `app.css` облака и другие чужие коммерческие исходники.
- Не объявлять этап завершённым без реальных проверок.
- Не писать в общую память агента — решения и журнал ведутся в `docs/PLAN.md` и `PRIVATE.md`.
